## 2. Model Architecture & Pipeline

```text
                  1. Input Resume Text
  ("Python, pandas, SQL, machine learning, scikit-learn, statistics...")
                           │
                           ▼
               2. Text Preprocessing & Cleaning
         • Lowercase normalization
         • Tokenization into unigrams and bigrams ((1, 2))
         • Document frequency pruning (min_df=2, max_df=0.95)
                           │
                           ▼
                3. TF-IDF Vectorization
         • Sublinear term frequency log-scaling: 1 + log(tf)
         • Inverse Document Frequency (IDF) weighting
         • L2 Euclidean normalization
         • Output: 1,594-dimensional sparse numerical vector
                           │
                           ▼
          4. Multinomial Logistic Regression (Softmax)
         • Linear score: z_k = W_k · X + b_k
         • L2 Ridge regularization (C = 1.0, solver = 'lbfgs')
         • Softmax activation across 8 career classes
                           │
                           ▼
                    5. Model Outputs
         • Predicted Career Track (argmax probability)
         • Confidence Probability Score (0% - 100%)
         • Top 3 Ranked Career Matches with percentages
```

## 7. Limitations & Academic Transparency

1. **Synthetic Data:** The training and evaluation data is synthetically generated using role-specific technical profiles. It is not scraped from commercial job boards or private corporate HR systems.
2. **Controlled Vocabulary:** The synthetic text generator uses clean keywords and standard phrases. Real resumes exhibit grammatical errors, OCR artifacts, non-standard section headers, and colloquial phrasing.
3. **Closed-World Assumption:** The model can only assign resumes to one of the 8 supported career categories. Resumes from other fields (e.g., Embedded Systems, Mobile Development, UI/UX) will be mapped to the closest available category.
4. **Bag-of-Words Semantics:** TF-IDF weights words based on frequency and document rarity, but does not capture deep semantic word order or candidate seniority (e.g., "studying Python" vs "10 years leading Python teams").
5. **No Production Integration:** This model is maintained strictly as an offline educational prototype and is not wired into the live web application.

## 8. Complete Answers to 44 Faculty Viva Questions

### 1. What model did you train?
We trained an offline supervised text classification model that maps unstructured resume text into 8 standardized technical career categories and computes class confidence probabilities.

### 2. What algorithm did you use?
We used a sequential scikit-learn pipeline combining **TF-IDF Vectorization** (for text feature extraction) and **Multinomial Logistic Regression** (with L2 Ridge regularization and L-BFGS optimization).

### 3. Why did you choose that algorithm?
Resume classification produces high-dimensional sparse feature vectors (1,594 features). Logistic Regression handles sparse matrices efficiently, trains in seconds, provides fully interpretable linear weights, and directly outputs calibrated probabilities via Softmax.

### 4. How many classes are there?
There are **8 classes**.

### 5. What are the class names?
Backend Developer, Cybersecurity Analyst, Data Analyst, Data Scientist, DevOps Engineer, Frontend Developer, Full Stack Developer, and Machine Learning Engineer.

### 6. How many records are in the dataset?
There are **1,600 total records** in `dataset/synthetic_resume_career_dataset.csv`.

### 7. How many records are in each class?
Exactly **200 records per class** (perfectly balanced at 12.5% each).

### 8. What are the input features?
The raw input is unstructured resume text. After TF-IDF vectorization, this text is converted into a **1,594-dimensional numerical feature vector** of unigrams and bigrams.

### 9. What is the target/output?
A categorical career label representing one of the 8 technical career categories (`career` column).

### 10. How was the resume text converted into ML features?
Using scikit-learn's `TfidfVectorizer`, which tokenizes the text into single words and bigrams, filters rare and corpus-wide terms, scales term frequency logarithmically, weights by inverse document frequency, and applies L2 vector normalization.

### 11. What preprocessing was performed?
Lowercasing, unigram and bigram extraction (`ngram_range=(1, 2)`), frequency thresholding (`min_df=2`, `max_df=0.95`), and sublinear term frequency scaling ($1 + \log(\text{TF})$).

### 12. What is TF-IDF?
Term Frequency – Inverse Document Frequency. It measures term importance by multiplying how often a word appears in a specific resume (TF) by how rare it is across all resumes in the corpus (IDF), penalizing generic words and highlighting role-specific skills.

### 13. What is Logistic Regression?
A linear classification model that calculates class scores as a weighted sum of input features ($z_k = W_k \cdot X + b_k$) and maps them into a normalized probability distribution using the **Softmax function**.

### 14. How was training performed?
Using a scikit-learn `Pipeline`. The dataset was split 80/20, the TF-IDF vectorizer was fitted strictly on the training set, and the logistic regression weights were optimized using the L-BFGS solver over up to 2,500 iterations.

### 15. What train/test split was used?
An **80/20 stratified split**: 1,280 samples for training (160 per class) and 320 samples for testing (40 per class).

### 16. What random seed was used?
`random_state = 42`, guaranteeing 100% deterministic reproducibility across runs and environments.

### 17. What is the training accuracy?
**100.00% (1,280/1,280)** on the training split.

### 18. What is the testing accuracy?
**100.00% (320/320)** on the held-out test split.

### 19. What is precision?
The ratio of true positive predictions to total predicted instances for a class ($\frac{\text{TP}}{\text{TP} + \text{FP}}$). Our model achieved 1.0000 across all classes on the test set.

### 20. What is recall?
The ratio of true positive predictions to total actual instances of a class ($\frac{\text{TP}}{\text{TP} + \text{FN}}$). Our model achieved 1.0000 across all classes on the test set.

### 21. What is F1-score?
The harmonic mean of precision and recall ($2 \times \frac{P \times R}{P + R}$), providing a balanced measure of classification quality.

### 22. What is macro F1?
The unweighted arithmetic mean of F1-scores across all 8 classes, giving equal weight to every class. Our macro F1 is **1.0000**.

### 23. What is weighted F1?
The average of class F1-scores weighted by class support. Because all classes have equal support (40 test samples), weighted F1 is **1.0000**, identical to macro F1.

### 24. What does the confusion matrix show?
An $8 \times 8$ table showing true career classes in rows and predicted career classes in columns. In our test set, all 320 samples fall along the main diagonal (40 per class) with zero off-diagonal values, confirming zero errors on this evaluation split.

### 25. Which class has the most samples?
All classes have an equal number of samples: **200 samples each**.

### 26. Which class has the fewest samples?
None. The dataset is perfectly balanced.

### 27. Which classes are confused with each other?
On this synthetic test set, there are zero misclassifications. However, looking at prediction probability distributions, the closest overlaps exist between **Data Scientist and ML Engineer**, **Full Stack and Frontend/Backend Developer**, and **DevOps and Backend Developer**.

### 28. What are the most important terms/features for each class?
- Backend Developer: `postgresql` (+1.76), `fastapi` (+1.54), `api` (+1.34)
- Cybersecurity Analyst: `security` (+1.58), `incident` (+1.54), `network` (+1.50)
- Data Analyst: `tableau` (+1.63), `data` (+1.61), `reporting` (+1.59)
- Data Scientist: `statistics` (+1.46), `numpy` (+1.45), `seaborn` (+1.18)
- DevOps Engineer: `ci` (+1.86), `ci cd` (+1.86), `terraform` (+1.70)
- Frontend Developer: `interfaces` (+1.50), `vite` (+1.46), `tailwind` (+1.44)
- Full Stack Developer: `mongodb` (+1.71), `applications` (+1.61), `full stack` (+1.54)
- Machine Learning Engineer: `pytorch` (+1.81), `deep learning` (+1.60), `deployment` (+1.58)

### 29. How does a new resume get predicted?
The resume text is lowercased, transformed into a 1,594-element TF-IDF vector, scored by the linear weight matrix ($W \cdot X + b$), and converted into 8 probabilities using Softmax. The class with the highest probability is returned.

### 30. What does the prediction probability mean?
It represents the model's mathematical confidence based on how strongly the resume's TF-IDF features align with each career's learned decision hyperplane.

### 31. Can I manually enter a resume and get a prediction?
Yes. Running `python demo_predict.py` opens an interactive prompt where you can paste any resume text and immediately see predictions and probabilities.

### 32. Can I show multiple example predictions?
Yes. Running `python sample_predictions.py` executes predictions on 10 realistic held-out candidate resumes across all 8 career paths and prints a formatted verification table.

### 33. How are skills related to careers?
Skills are the primary distinguishing attributes of careers. In `dataset/career_skill_mapping.csv`, each career is mapped to 13–14 core and supporting skills with explicit importance weights.

### 34. How many skills are present in the skills dataset?
There are **87 unique technical skills** across 9 categories in `dataset/skills_dataset.csv`.

### 35. How many assessment questions are present?
There are **48 multiple-choice questions** in `dataset/assessment_questions.csv`.

### 36. How many questions belong to each career, skill, and difficulty?
- Per Career: Exactly 6 questions per career (8 careers $\times$ 6 = 48).
- Per Difficulty: Exactly 16 Beginner, 16 Advanced, and 16 Expert questions.
- Per Skill: Covers 40 distinct technical skills.

### 37. What are the Beginner, Advanced, and Expert levels?
- Beginner: Fundamental syntax, definitions, and basic concepts.
- Advanced: Practical implementation, APIs, edge cases, and debugging.
- Expert: Architecture patterns, scalability trade-offs, reliability, and security.

### 38. How are the questions structured?
Each record has 11 columns: `question_id`, `career`, `skill`, `difficulty`, `question`, 4 options (`option_a` to `option_d`), `correct_answer`, and an `explanation`.

### 39. How does the skill dataset support the assessment concept?
After identifying a candidate's target career, the system identifies required skills from the mapping, evaluates candidate claims, and administers skill-specific questions to generate an objective proficiency score.

### 40. What are the limitations of the model?
The dataset is synthetic, the model operates in a closed world of 8 classes, TF-IDF cannot understand semantic sentence context or candidate seniority, and the model is not an automated hiring tool.

### 41. Is this model currently integrated into the production app?
**No.** It is maintained separately inside `Model/` as an experimental proof-of-concept. The production application uses its existing FastAPI backend and AI/LLM API pipeline.

### 42. Is the dataset real or synthetic?
It is **synthetic**, generated programmatically using domain skill templates with fixed seed 42.

### 43. Why is the accuracy 100% on this dataset?
Because the synthetic resumes were created using role-specific skill clusters that form clean, linearly separable decision boundaries in the 1,594-dimensional TF-IDF space. This confirms pipeline correctness, not real-world performance.

### 44. What would be required before deploying this model in a real production environment?
Collecting 20,000+ real, anonymized resumes across 50+ roles, multi-expert human annotation, upgrading to contextual transformer embeddings (e.g., Sentence-BERT), implementing an out-of-distribution rejection class, and auditing for demographic bias.
